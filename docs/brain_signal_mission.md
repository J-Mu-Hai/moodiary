# 大脑信号与使命设计（Brain Signal & Mission）

> 智能体「主动性」的完整设计：什么信息喂给大脑、大脑带着什么使命决策、
> 初始化怎么启动、日常怎么运转、任务怎么闭环。
> 状态：**设计稿，待审**。与 [agent_task_spec.md](agent_task_spec.md) 互补——那份讲"智能体有哪些能力"，
> 这份讲"智能体靠什么驱动、为什么驱动"。
> 实施分批见文末；批次 1（0 点归位 + 任务停滞检测 + 行为逻辑例行）与
> 信号 2/3/4/5/7、初识任务、画像 v2 已具备。

---

## 一、一句定位

> **7 路信号 → 带使命的大脑（角色卡定义人格）→ 调用函数规划执行 → 反馈闭环**

智能体做两件事：
1. **和用户成为朋友**——陪伴、记住、可依赖；
2. **帮用户成为更好的人**——完成自己的计划、养成更好的行为习惯。

## 二、信号层（7 路）

| # | 信号源 | 语义 | 现状 |
|---|---|---|---|
| 1 | 对话窗口输入 | 用户在聊天框说话 | 🔜 待做（需防"直答 + 又规划一遍"的双重回应） |
| 2 | 日记内容变化 | 写完稳定 → 标记待分析 | ✅ `diary_stable` |
| 3 | App 使用类别变化 | 日基线占比变化 >30% | ✅ `usage_category_changed` |
| 4 | 画像基础内容 | 空 / 缺基础认知 | ✅ `profile_uninitialized` / `profile_incomplete` |
| 5 | 已制定的任务规划 | 长期任务停滞回访（24h） | 🟡 `longterm_overdue`（成败模式未回喂） |
| 6 | 用户任务管理板块 | 有 pending 任务、N 天未动 | ✅ `task_stall`（任务管理分类无「完成」标签且 ≥3 天未动） |
| 7 | 用户制定的规则 | if-条件 then 动作（确定性） | ✅ AgentRuleStore |

**检测节流原则**：检测要快（分钟级），决策要稳（大脑可 noop）。
双层节流：每源 30~60 分钟内存节流 + 大脑同类型 6h 冷却。
7 路信号只负责「变化 / 停滞 / 缺失」三类语义的**捕捉**，不直接打扰用户。

## 三、大脑层

### 3.1 角色卡（人格 + 使命）
- 人格：温晚照（`sonder_persona.txt`），注入 对话 / 规划 / 复盘 三处，保证同一人格。
- **使命段（待加）**：和用户成为朋友；帮用户成为更好的人、完成计划、养成习惯。
- 风格约束：提醒永远 gentle、不催促、不居高临下；修补原则（不删除不覆盖不篡改）约束规划——不做强硬的催促型任务。

### 3.2 规划
- 输入：信号 + 画像（9 类，带置信度/来源）+ 可用函数
  （`getDiaryByDateRange` / `getTaskAnalysis` / `get_usage_timeline` / `env_snapshot` / `get_lore` / `getUniversalValues` / `speak`…）
- 输出：`immediate` / `scheduled` / `longterm` 三类任务。
- **授权面板（可选增强，待定）**：AI 动作开关（对话/语音/锁屏/开日记/分析各一个开关）
  + 信号灵敏度（哪些信号可响应）+ 风格边界（用户可见可调）。

## 四、初始化

1. 存在**未分析的日记 / 任务规划** → 标记待分析，排入**0 点归位**批量分析。
2. **画像基础词条（身份/年龄）为空** → 找合适时机启动「初识」任务
   （`ask_user` 第一次沟通 → `ingestChatInsight` 沉淀基础认知）。

## 五、每日例行（绝对不变任务）

不进 AI 决策，作为每日固定骨架（可靠，不靠 AI 自觉）：

1. **行为逻辑采集**——从本地已有数据推断，纯数据、不主动打扰：
   - 几点睡 / 几点起：由 `get_usage_timeline` 首尾会话推断；
   - 上午 / 下午 / 晚上计划：日记 + 用户任务板块 + 使用时间线拼接。
2. **0 点归位**（每天 00:00，处理**刚结束的这一天**）：
   - 分析当天未读日记 / 任务 → 沉淀画像；
   - 复盘当天行为逻辑，**向用户呈现行为逻辑摘要**（这是"确认行为逻辑"的唯一时刻，
     用户顺手可纠正；不额外在睡前打扰）；
   - 画像沉淀（`MemoryService.consolidate` 并入归位，作为每晚一次的统一沉淀）。

## 六、执行与反馈

1. 任何信号变化 → **立刻**入脑分析 → 判定是否行动（`noop` 是合法答案）。
2. **交互型任务**（`ask_user` / `start_chat` / `block_screen` / `open_diary`）
   → 强制反馈闭环：执行 → 用户反应 → **继续 / 调整 / 结束**。
3. **通知型任务**（`tts` / `analyze_diaries`）→ 轻量记录，不硬加反馈
   （无可观察的用户反应，硬加会变成连环追问）。

## 七、边界（不做什么）

- **检测快 ≠ 打扰多**：大脑有权 noop；6h 冷却兜底。
- 不因「想方设法弄清行为逻辑」而窥探：只用本地已有数据推断，不问打扰性问题。
- 不双重回应：对话入脑必须去重，避免"直答 + 又规划一次"。
- 规则层（用户写死）是确定性主力；AI 只处理无规律的涌现事件。
